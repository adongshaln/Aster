# ADChat

ADChat 是一个原生 Android 多 API 客户端，支持将对话和绘图分别路由到不同的 OpenAI 兼容服务。

- 复制、重试、继续生成和重新生成统一改为紧凑自定义操作按钮
- 操作按钮只按实际内容测量，确保图标和文字在窄屏及短回复下完整显示

## v1.33.0

- 支持纯图片消息，也支持图片与文字组合发送
- OpenAI Chat Completions 与 Responses API 均使用对应的多模态图片格式

## v1.31.0

### 20 张全局图片并发容量

- 漫画翻译单批选择上限由 4 张提升到 20 张，首次选择和后续追加都支持一次多选
- 并发限制不再按“任务数量”计算，而是按仍在处理的图片数量计算；所有批次合计最多 20 张
- 支持 `20`、`10+10`、`5+5+5+5` 等任意拆分方式；提交新批次时会精确检查“当前处理中图片 + 新批图片”是否超过 20
- 同一批中的页面完成后会立即释放对应图片槽位，不必等待整批保存结束才能继续补充任务
- OkHttp 全局请求与单主机并发同步提升到 20，漫画分析和逐页生图共享统一闸门，实际网络请求不会突破上限
- 状态卡同时显示运行任务数和实时图片占用，例如“2 项 · 15/20 张”；主按钮显示当前图片容量而非旧版 12 项任务数
- 20 页分析不会直接把全部高分辨率原图编码进辅助模型请求：应用会为辅助分析生成最长边 1600 像素的轻量副本，显著降低 Base64、JSON 和堆内存占用
- 原图仍用于逐页生图；仅当单张超过 6 MB 时才生成最长边 4096 像素的高质量上传副本，兼顾构图细节与批量稳定性
- 图片优化在后台顺序执行，预览继续使用用户原始 URI，不降低应用内查看清晰度

## v1.30.1

### 修复供应商网关约两分钟主动超时

- 已确认此前将客户端等待放宽到 45/90 分钟仍不够：部分 OpenAI 兼容网关会在非流式请求约两分钟时主动返回 504/524，客户端无法单方面延长供应商的上游限制
- 漫画辅助分析现改为真正的 SSE 流式多模态请求；Responses API 会在数秒内返回 `response.created` 等事件，持续保持网关连接活跃
- Chat Completions 类型的辅助模型同样启用流式返回，并逐块组装最终结构化 JSON
- 供应商忽略 `stream`、直接返回普通 JSON 时仍可在同一次请求中兼容解析，不会额外提交第二次付费请求
- 流式分析未完整结束或 JSON 不完整时继续阻止后续生图，避免把残缺翻译方案提交给图片模型
- HTTP 408/504/524 现在会明确标记为“供应商网关主动结束长请求”，不再误导为应用本地等待时间不足
- 使用提供的 `gpt-5.6-sol` 接口完成现场验证：Responses 多模态流式请求约 3 秒收到首事件；应用真实漫画分析链路也已完整返回并通过 JSON 解析

## v1.29.0

### 辅助视觉模型两阶段漫画翻译

- 漫画翻译升级为两阶段流程：辅助视觉模型先统一理解同批次全部页面，再将逐页翻译方案交给生图模型执行原位替换
- 辅助模型一次接收用户上传的 1–4 张漫画原页，分析跨页剧情、人物关系、世界观、称谓、语气和统一术语
- 分析结果采用严格结构化 JSON，包含共享设定、人物口吻、术语表，以及每页按阅读顺序整理的原文、最终译文、说话者、语气和位置提示
- 应用拆分 JSON 后，将“当前页原图 + 共享设定 + 当前页译文”分别发送给生图模型，仍保持最高 4 页并发，避免串页或拼图
- 生图模型不再承担主要语义判断，只负责按确定译文擦除源字、匹配字体并原位排版，提升翻译一致性
- 漫画开关旁新增紧凑“辅助”模型胶囊，可从已有供应商与模型中选择，不扩大漫画模式组件
- 辅助模型路由独立于当前对话和绘图模型，选择会加密持久化，并随 API 配置导入导出
- 分析阶段使用独立长连接、稳定幂等 Key 和禁隐式重试策略；分析失败时不会继续提交生图请求
- 同批次失败页重试会复用已完成的分析结果，无需再次理解全部页面
- 图片内文字被明确视为待分析数据，不能作为提示注入指令；缺页、重复页和非法 JSON 会在生图前拦截
- 已使用提供的 `gpt-5.6-sol` 接口完成真实多模态兼容性测试，Responses 图片输入成功识别测试图文字
- 新增分析提示词、JSON 解析、页码兼容、图像编辑指令和多模态长请求策略测试

`keystore.properties`，再填写自己的 JKS 路径与凭据；未配置签名时仍可正常构建 Debug，Release
会生成未签名产物。

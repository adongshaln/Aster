## 3. 必须显式补齐的语义边界

### G1 人物状态、关系与认知（完整首版阻塞）

`StoryMemoryOrganizer.parse` 把 CurrentState、DirectedRelationship、CharacterKnowledge 全部转换为 PlotEvent，并加“本轮观察”文字；`StoryMemoryStore` 自动保存为 ProseOccurred，主体/客体实体引用缺省为空。枚举与数据库字段存在，不等于功能已经实现。

`StoryContextComposer` 把所有非 Inference 的 active 资料放入正式资料集合；`renderMemory` 只输出 kind 和 content，不输出 nature。因而即使引入 CharacterBelief，也缺少可靠的主观/客观提示边界。需要先补 schema、实体引用、nature、定向关系和可变状态键，再验证怀疑、伤势恢复、位置迁移等场景。

### G2 冲突与用户纠正优先级（完整首版阻塞）

当前固定资料不会被自动修改，但正文冲突不会生成可处理的冲突项。需保存双方来源、阻止冲突条目直接成为无条件事实，并允许明确选择采用/保留待定。不能以 append-only 等同冲突解决。

### G3 长故事记忆覆盖与成本（完整首版阻塞）

当前的 Summary 类型只是可追加记录，没有覆盖消息范围、独立阈值摘要任务或依赖失效链。创作预算不知道哪些完整轮次尚未整理；整理输入超限会失败。需补整理覆盖范围、摘要源版本清单与超限处理，随后测试连续长故事及失败积压。故事界面尚无整理用量/调用次数展示，不能估算为“每轮固定成本”。

### G4 讨论到正文的操作闭环（原计划缺口）

缺“讨论这段”“用于后续 / 重写原段 / 修改设定”、相关回复旁候选卡片、编辑后采用、模型驱动的重写与旧用户输入编辑。当前修订是用户手动编辑正文，不能称为模型重生成能力。

自然语言自动采用可以作为更保守的产品取舍继续延后，但需明确记录为范围调整；本核对不替用户默默批准删去原需求。

### G5 恢复与撤销边界（原计划部分实现）

已有物化快照另写、路线切换、手动反向日志和最新批次整体反向日志。它们不是任意日志位置的重放系统。后续依赖、关联决定待复核、独立设定重新适用及受影响位置展示尚缺。历史路线入口是为安全保存旧后续增加的实现，不代表扩展路线管理属于首版已授权新目标。

## 4. 建议执行顺序与完成门槛

1. **先修 G1/G2**：定义最小结构化实体/状态/认知和冲突协议；补数据库与上下文端到端的确定性测试。禁止仅修改整理器提示词后宣称完成。
2. **补 G3**：保证未整理正文与摘要覆盖范围可计算；超预算明确处理，并记录调用/用量是实际、估算还是未知。
3. **补最小 G4/G5 闭环**：选段讨论、明确应用目标、模型重写和关联决定复核。每项单独提交；沿用当前分支和签名。
4. **执行下面的真实 Gemini 小样本验收**，只使用虚构故事；不把私人正文、Key 或完整网络日志提交到仓库。
5. **交付 #100 或后续明确 SHA 的测试 APK 进行真机验收**，修复发现的问题后再决定合并/版本/发布。

可先用当前包试用基础功能，但不能用“试用没问题”代替尚未实现的核心边界。若选择提前发布缩减版，应明确名称和缺失能力，不能沿用完整首版验收结论。

| R7 | 停止一条长回复，检查档案；退出并重启 | 部分正文保留，未作为正式事件；未重复请求已完成整理 |
| R8 | 修订末尾或从有快照的 R6 较早正文另写，删去受伤事件 | 当前路线不再读取旧伤资料；原路线与后续保留；切回一致 |
| R9 | 采用一个候选后立刻整体撤销，再恢复；再手动修改资料尝试撤销旧批次 | 候选与资料同步；后续冲突明确拒绝，不产生半次写入 |

这些是验收标准，不是预先填写的成功记录。R5/R6 等实现缺口应先补代码，再用真实模型验收；不要反复调用模型来掩盖缺失的数据能力。

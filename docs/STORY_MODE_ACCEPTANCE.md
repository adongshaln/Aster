## 实现方式与限制

- 恢复采用有效版本、物化快照和依赖校验；日志支持有条件的反向操作，**没有通用任意位置的日志重放引擎**。历史中段重写保留旧后续为另一条路线。
- 模型输出为有限新增事实/候选及疑似矛盾。状态通过来源顺序计算当前值，保留旧观察；不会让模型任意更新、结束或删除数据库记录。
- 作者计划为有用途标签的文字；没有结构化触发条件调度器。人物别名解析以已有精确映射为准，不做猜测性合并。
- 自由文本矛盾由模型提出、应用匹配来源、用户裁决。记忆超出整理请求的资料选择范围时，不能保证发现所有冲突。
- 明确引用的讨论决定可追踪正文依赖；删除/大幅改写引用块或仅凭自然语言暗指旧剧情，不保证自动建立依赖。
- 重写界面展示最近一次候选；失败、停止和未完整候选不能采用。没有多候选历史浏览器。
- 超长整理最多 16 段；单条分段摘要最多 16 + 4 + 1 次请求，正常短回复不走此流程。部分结果仅作恢复检查点，最终完整提交才改变正式记忆。
- 用量展示应用请求次数及接口报告 token 下界，未报告部分为未知，不是假设零成本。强停后不承诺后台继续；重新打开时恢复任务。
- 故事数据库不在现有服务配置导出中。原有普通聊天没有迁移或改写。
